The 4-Tier Defensive Caching Hierarchy
Every translation request passes through four independent defensive layers before ever reaching external AI APIs:
Tier 1: Client-Side LocalStorage & RAM Memory
0ms Latency • 0 Bytes Network
Once a reader views an article in a selected language (e.g. English, Marathi, Chinese), the entire translated object (Headline, Summary, 30s Highlights, Subtitle, and Full Body) is saved to the browser's localStorage under ps_art_obj_{articleId}_{lang}. When the reader returns to the story or navigates between tabs, it loads instantly in 0ms without sending a single network packet to the server.
Key: ps_art_obj_art-1793864819037_zh-TW | Storage: Browser LocalStorage | Network: 0 KB
Tier 2: Server Persistent Database Cache (translations.json)
7ms - 40ms Latency • 0 Gemini API Calls
When any user anywhere on Earth requests an article in a target language for the first time, the verified translation is written to server/data/translations.json. For all other readers worldwide, the server fetches the record directly from disk in 7 to 40 milliseconds, completely bypassing the Gemini API.
Key: {articleId}:{lang} | File: server/data/translations.json | Cloudflare D1 Database Compatible
Tier 3: In-Flight Promise Concurrency Lock
Surge Protection • 100% Race-Condition Free
During breaking news events, if 50 or 100 readers simultaneously open a fresh Hindi article in English at the exact same second, the server does NOT launch 50 API calls. The first request locks inFlightTranslations, and the other 49 requests attach to the running Promise, receiving the exact same output. Exactly 1 API call executes.
Engine: Map(storeKey, Promise) in server memory | Auto-cleanses in finally block
Tier 4: Cryptographic Hash & Integrity Validation Gate
Automated Invalidation • Quality Shield
Every cached translation stores a SHA-256 contentHash derived from ${title}:::${body}. If a reporter edits the article in the newsroom editor, the hash changes and forces a fresh translation on next read. Unchanged stories never expire. Furthermore, validateTranslationIntegrity() rejects truncated outputs (< 35% paragraphs) or error strings, cleanly falling back to Hindi rather than corrupting the database.
Algorithm: SHA-256 contentHash | Paragraph Preservation Threshold: >= 35% of original
Storage Watchdog: Dual-Threshold LRU Emergency Shield
Disk Hygiene • 500 MB Database Ceiling
Monitors database disk footprint against Cloudflare D1 limits: 80% Warning Alert (400 MB) flags an admin status banner. 90% Emergency Cleanup (450 MB) auto-evicts least recently accessed translations using last_accessed_at timestamps down to a safe 70% post-cleanup target (350 MB).
Ceiling: 500 MB | Alert: 80% (400 MB) | Auto-Purge: 90% (450 MB) | Post-Cleanup: 70% (350 MB)
